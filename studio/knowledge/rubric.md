# 天狼スタジオ 審査ルーブリック（critic 用）

制作ワークフローの手順8（`playbook.md` §2）で、**作品を作っていないエージェント**が使う審査基準。
審査役はこのファイルを最初から最後まで読み、指定の JSON だけを返す。

---

## 1. 審査役への指示

あなたは天狼スタジオの上級モーションデザイン審査員である。この作品は**あなたが作ったものではない**。
目的は、作品を「ハイエンドの商業品質」に届かせること。優しさは役に立たない。具体性がすべて。

### 1.1 渡されるもの（これ以外は見ない）
- 完成 mp4 のパス
- レビュー用の画像: 拍ごとのコンタクトシート、0.5秒ごとのシート、カット前後のストリップ、ヒーローモーメントの 0.1〜0.2 秒刻み、等倍クロップ
- 数値: ffprobe（尺・解像度・fps・色タグ）、ebur128（LUFS・TP）、master.py --qc（黒味・無音）、静止区間、cue とオンセットのズレ、可読時間、帯域バランス
- brief の抜粋: 目的・視聴者・掲載先・コンセプト1行・スタイルカード（シグネチャ）・合格ライン
- このルーブリック

作り手の説明・修正ログ・自己評価は**渡されないし、求めない**。

### 1.2 見かた
1. 先に数値で仕様違反を拾う（§4 の spec_check）。
2. 0.5秒シートで全体の形 → 拍ごとのシートでリズム → カット前後のストリップで転換 → 刻みのシートでヒーローモーメント → 等倍クロップで細部（エッジ・組版・エイリアス・バンディング・豆腐）。
3. 観客として順に読み、各リード（観客が理解すべきこと）が何フレームもらえているか数える。
4. 音は聴けない前提で、波形の数値・スペクトログラム・オンセットのズレから評価し、そうしたことを `notes` に書く。

### 1.3 厳しさ
- 尺度: 5 = 学生として及第、6 = まともなテンプレ水準、7 = しっかりしたプロ、8 = ハイエンド代理店、9 = アワードのショートリスト、10 = 世界最高。
- **初稿の大半は 5〜7 が妥当。水増ししない**。迷ったら低い方を付ける。
- 点数ごとに根拠のタイムコードを最低1つ書く。見ていない点は採点しない（null にして理由を書く）。
- 7 を付けるのは「直すべき大きな問題が見当たらない」とき。8 以上は「同業者が見て感心する点」を具体的に挙げられるときだけ。
- 次のものは**クリティカル**（該当軸は最大 4、verdict は publish にできない）:
  汎用的・AI テンプレに見える／不自然な日本語・誤字／フォールバックフォント・豆腐／仕様違反（尺・解像度・fps・ラウドネス・TP・色タグ）／偽の数値・実績・レビュー／facts.json に無い数字／安全域の外の重要な文字／意図しない黒味・空白フレーム。

## 2. 7つの軸とアンカー

| 軸 | 見ること |
|---|---|
| style_fidelity | 選んだスタイルが一目で分かる。スタイルカードの不変条件とシグネチャが全部、正しく入っている |
| concept_wow | 1行で言えるアイデア、0.5秒のフック、誤解しようのないヒーローモーメント（尺の60〜75%）、満足のいくエンド画、冒頭と韻を踏む結末 |
| motion_craft | イージング・スペーシング・ずらし・予備動作とフォロースルー・弧・転換・モーションブラー。死んだ動き・等速・ガタつき・左右対称の機械的な動きがない |
| design_typography | 構図・階層・グリッド・余白・色の節制、和文の組版（禁則・約物・改行位置・字間）、可読性 |
| finish_texture | スタイルに合った光・質感・グレイン・ディテール。バンディング・エイリアス・ちらつき・圧縮の破綻がない |
| sound_sync | 音楽の質とジャンルの合致、SE の設計、絵のヒットと音のオンセットの一致、ダッキング、無音と J/L カット、ミックスとマスター |
| technical | 仕様の遵守、フォントの読み込み、決定性、ループの継ぎ目、グリッチ・ポップ・クリップがない |

### アンカー（1 / 4 / 7 / 10）

**style_fidelity**
- 1: どのスタイルか分からない。指定と違う見た目
- 4: スタイルの雰囲気はあるが、シグネチャの半分以上が欠けているか間違っている
- 7: 専門家が1秒でスタイル名を言える。シグネチャが全部入っているが、1〜2個が浅い
- 10: そのスタイルの最良の例として教材に使える。不変条件を守ったまま新しい読み方を見せている

**concept_wow**
- 1: アイデアがない。素材を順に並べただけ
- 4: アイデアはあるが、フックが弱いかヒーローモーメントが埋もれている。最後まで見る理由が薄い
- 7: 1行で言えるアイデア、0.5秒で掴むフック、はっきりしたヒーローモーメント、気持ちよく締まるエンド画
- 10: 見終わって人に見せたくなる。ネイティブムーブがピークに置かれ、結末が冒頭と見事に韻を踏む

**motion_craft**
- 1: 等速・同時・ポンと出る動きばかり。ガタつく
- 4: イージングは付いているが全部同じカーブ・同じ量。予備動作もずらしもない。転換がフェード頼み
- 7: 意図のあるイージング、2〜4フレームのずらし、拍の手前で動き出して拍で着地。転換を要素が運ぶ。速い動きにブラー
- 10: 1コマずつ見ても隙がない。重さの違い、弧、オーバーラップ、フォロースルーが全部の動きで効いている

**design_typography**
- 1: 構図が崩れ、文字が読めない・はみ出す・重なる
- 4: 読めるが窮屈か散漫。色が多い。和文の改行や約物に不自然な箇所がある
- 7: どの静止画もポスターとして成立する。階層が明快、余白が効き、アクセント色は1色、和文の組版が正しい
- 10: 一流のエディトリアルデザイン。グリッドと文字の対比が作品の意味を語っている

**finish_texture**
- 1: バンディング・エイリアス・ちらつきが目立つ。素のベクターが安っぽい
- 4: 大きな破綻はないが平板。光や質感がスタイルに合っていない、またはグロー・グレインのかけすぎ
- 7: スタイルが求める所にだけ光・質感・グレイン。グラデは滑らか、細線はちらつかない
- 10: 光と質感が作品の格を決めている。どの等倍クロップにも粗がない

**sound_sync**
- 1: 音がない、または映像と無関係。ラウドネスが外れている
- 4: 音楽は合っているがヒットが拍・動きとずれる（±2フレーム超）。SE が多すぎるか少なすぎる。低域が重い
- 7: 絵のヒットが音のオンセットに ±1フレームで乗る。意味のある動作に音、本当の無音とJ/Lカットがあり、-14 LUFS・TP ≤ -1
- 10: 音と絵が1つの楽器のよう。無音明けの1音、サウンドロゴ、ダッキングまで設計されている

**technical**
- 1: 再生できない、尺や解像度が違う、豆腐がある
- 4: 仕様は満たすが、ポップ・1フレームの欠け・ループの段差・色タグ欠落などが残る
- 7: 全仕様を満たし、数値ゲート（`playbook.md` §1）が全部通る
- 10: 7 に加え、決定性・ループ・複数比率の書き出しまで検証済みで、再ビルド手順が完全

## 3. DIRECTOR ゲート（yes / no / na）

すべて yes（または理由つきの na）でないと publish にしない。no は必ず fixes に入れる。

| id | 確認すること |
|---|---|
| hook_05s | フレーム0で絵が完成していて、0.5秒以内に何の動画か分かる（SNS）／3秒以内にフック（長尺） |
| one_subject | 1被写体・1目的・1ターン。同時に2つのことが起きていない |
| hero_60_75 | 誰が見ても分かるヒーローモーメントが、尺の 60〜75% に1つある |
| end_hold | エンド画が 0.8〜1.2 秒ホールドされ（微動あり）、ロゴ・CTA が読める |
| ending_rhymes | 結末が冒頭と韻を踏む（同じ位置・モチーフの変化形） |
| camera_vocab | カメラ操作が 3種以上（15秒以下）／4種以上（30秒以上）で、それぞれ目的がある |
| tempo_contrast | 明確な加速か減速が1回、息をつくホールドが1回ある |
| real_silence | 本当の無音（デジタルゼロ）が1回以上（短尺）／2回以上（30秒以上）。無音明けの音が重要な音 |
| jl_cut | J/L カットが1回以上（短尺）／2回以上（30秒以上） |
| transitions | 転換が要素に運ばれている。既定のクロスフェード・意図しない素のカット・空白フレームがない |
| sound_for_action | 意味のある見える動作に音があり、SE は sync point（衝撃＝トランジェント、whoosh＝通過のピーク、riser＝終端）で合っている |
| read_time | 全テロップが max(1.8秒, 読む時間＋0.6秒) 以上表示され、声より先に点灯していない |
| subject_size | 要所で主被写体が画面の高さの 1/3 以上 |
| safe_area | 重要な文字が安全域（縦: 上260・下420・左右90px、横: 端から5%）の内側 |
| no_banned | 禁止リスト（`playbook.md` §3.5）の表現がない（スタイルが求める例外を除く） |
| facts_only | 画面とナレーションの数字・固有名詞・主張がすべて facts.json 由来。偽の実績・レビューがない |
| silent_ok | 音を消しても意味が通じる（SNS・サイネージ） |
| not_a_rerun | 前作・テンプレートの焼き直しでない（構成・冒頭・看板ショット・カメラ経路・音楽の形・結末のうち4つ以上が違う） |
| loop_seam | ループ用途なら継ぎ目の差がゼロ（ループでなければ na） |

### 4.1 フィールドの決まり
- `t0` / `t1` は秒（小数2桁）。1点の指摘は t0 = t1。
- `critical` の各要素は `{"t0", "t1", "axis", "issue"}`。§1.3 のクリティカルに当たるものだけを入れ、該当軸の点を 4 以下にする。可読時間の不足などのゲート違反は critical ではなく fixes と director_gate で扱う。
- `fixes` は **5〜10 件**、影響の大きい順。細かい指摘を並べるより、大きな改善を少数出す。
- 各 fix の `how` には**数値を入れる**（秒・フレーム数・px・HEX・イージングカーブ・dB・BPM・字数など）。「もっと良くする」「調整する」は不可。
- **少なくとも1件は `type: "wow"`**（磨きではなく、コンセプトやヒーローモーメントを一段上げる修正）。他は `"polish"` か `"fix"`（仕様違反・クリティカルの解消）。
- `axis` は7軸のどれか。`expected_gain` は見込みの上がり幅（軸: 点）。
- DIRECTOR ゲートの no は、必ず対応する fix を1件以上入れる。
- `strengths_to_keep` に、直すときに壊してはいけない長所を1〜3個書く。
- `mean` は7軸の単純平均（小数2桁）。null の軸があれば除いて計算し、`notes` に書く。

### 4.2 合格ラインと verdict（2026-11-06 改定：ユーザーの指示「合格ラインは引き下げて、とにかく色々作成してデータを貯める。合格と合格未満を区別して保存」）
| verdict | 条件 |
|---|---|
| `publish` | 平均 6.0 以上、かつ 4 以下の軸がない、かつ critical が空 |
| `fix` | publish の条件を満たさないが、4 以下の軸がない |
| `rework` | どれかの軸が 4 以下（critical による上限 4 を含む） |

**等級**（作品の保存先と管理アプリの works.grade に使う）
| 等級 | 条件 |
|---|---|
| 一級 | 7軸すべて 7 以上、平均 7.5 以上、DIRECTOR ゲートがすべて yes / na（旧合格ライン。Apple の製品ページで 7.50 だった水準） |
| 合格 | 平均 6.0 以上、4 以下の軸がない |
| 合格未満 | それ以外。**中止せず完成まで作り、記録として保存する** |

審査は最大2ラウンド（初回＋修正後1回）。2回目の点で等級を決めて完成とする。

## 5. 修正側への指示（制作セッションが受け取ったとき）

1. 現在の映像とソースを `vN/` として保存する。
2. critical と fixes を**全部まとめて1ラウンドで**直す。もっと良い解決策に確信があれば差し替えてよいが、理由を書く。`strengths_to_keep` を劣化させない。
3. フル解像度で再レンダーし、数値ゲートを再確認し、修正が効いたことを該当タイムコードのフレームで確かめる。
4. 同じ審査役ではなく、新しい審査役（前回の審査結果を見せない）にもう一度だけ審査させる。
5. 適用した修正・見送った修正とその理由、修正前後の点数を報告書に書く。
