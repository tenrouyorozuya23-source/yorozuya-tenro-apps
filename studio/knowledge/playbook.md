## 共通の品質基準

| 項目 | 基準 |
|---|---|
| ラウドネス | SNS/Web: -14 LUFS ±1.0、トゥルーピーク -1.0 dBFS 以下 |
| 動画コーデック | H.264 High / yuv420p / CRF 17 / faststart、音声 AAC 192k 48kHz |
| 縦型の安全域 | 1080×1920 で上 260px・下 420px・左右 90px に重要な文字を置かない（SNSのUIが被る） |
| 最初の1秒 | SNS 向けは 0 秒目から文字か強い絵を出す。0.5秒以内に何の動画か分かるようにする（R001） |
| 黒味・無音 | 意図しない黒味 0.3 秒以上・無音 0.8 秒以上は不可（master.py が検出） |

## 映像（render.mjs）

- ページは `window.renderAt(t)` で時刻 t の絵を**決定論的に**描く。乱数はシード付きにする。
- BGM の `*.beats.json` を `--data` で渡し、`__DATA.bar_sec` / `beat_sec` / `cues` でカット・アニメを拍に合わせる。カットは小節頭、要素の出現は拍頭が基本。
- Canvas で使う Web フォントは `window.__ready` 内で `document.fonts.load('700 34px "Font"')` して事前に読み込む。DOM で使っていない書体は読み込まれず、明朝体に化ける（R001）。
- 大見出し（230px 前後）は 1080px 幅だと5文字で溢れる。`scrollWidth` を見て自動縮小する（R001）。
- 1080×1920・30fps は 1秒あたり約7秒でレンダリングできる（15秒で約105秒）。長尺は `--from` で分割して並列化を検討。
- 確認は `--still 秒:ファイル,...` で要所の静止画を出し、横に並べて（`convert +append`）1枚で目視する。コンタクトシート（1秒間隔）だけだと遷移の瞬間を見逃す（R001）。
- 光の演出は `globalCompositeOperation='lighter'` の放射グラデーションと回折スパイクで作ると安っぽくならない（R001）。

## 音（bgm.py）

- 外部音源は使わず、すべて数値合成。曲の設計は `song.json`（BPM・キー・コード進行・セクション・メロディ・キュー）。
- 15秒広告の型: 128 BPM × 8小節 = 15.0 秒ちょうど。イントロ2小節 → 本編4小節 → ロゴ2小節（stab + chime）（R001）。
- スマホのスピーカー前提で低域を盛りすぎない。サブベースは入れない、パッドは 160Hz でハイパス、キックの減衰は短め（R001）。
- 帯域バランスの目安: 本編で「20–200Hz の合計」が「200–2000Hz の合計」より +6dB 以内。R001 は +8dB で、まだ重い。
- キューの種類: `riser`（盛り上げ）、`impact`（ドロップ）、`stab`（ロゴ着地）、`chime`（場面転換・きらめき）。映像の大きな切り替わりにはキューを置く。
- 音を聴けない前提で、数値（帯域別エネルギー・ラウドネス・LR相関）とスペクトログラム画像で評価する。

## HP制作

- スマホ幅 390px を先に作り、1440px に広げる。Playwright で両方のスクショを撮って目視。
- 目標: Lighthouse モバイル Performance / Accessibility / SEO 90 以上。画像は WebP、幅指定、`loading="lazy"`、`alt` 必須。
- 架空店舗のサンプルであることをフッターに明記する（実在店と誤認させない）。

## SNS 運用

- 記事のトーン（告知 / ノウハウ / 実績紹介 / 季節ネタ）で、色・テンポ・BGMジャンル・テロップ量を切り替える。
- 投稿文は 1 行目で要点。ハッシュタグは 2〜3 個まで。
- X 投稿は 1 日 3 件まで。投稿URLは管理アプリに記録。
