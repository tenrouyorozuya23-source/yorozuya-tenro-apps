## 2. 制作ワークフロー

SKILL の「テスト」が手順 1〜6、「制作」が手順 7〜10 にあたる。各手順の成果物は `studio/projects/<id>-<slug>/` に置く。

1. **ブリーフ**: `brief-template.md` を写して `brief.md` を埋める。目的・視聴者・掲載先・尺・CTA・素材・事実（facts.json）・権利を先に決める。分からない事実はユーザーの `notes` を見て、無ければ既定値で埋めて進める。質問で止まらない（研究:lemo-opuscar）。
2. **トリートメント3案**: 方向の違う案を3つ書き、1つ選んで理由を書く。最初に思いつく案はたいていそのスタイルの定番（クリシェ）なので、それを1案目として書いたうえで残り2案を離す（研究:lemo-opuscar）。各案は「ログライン1行・フック・ヒーローモーメント・結末の韻」の4点で比べる。
3. **スタイル決め**: `styles.md` の用途別表から選び、スタイルカード（不変条件）を brief に貼る。禁止リストもここで確定する。
4. **拍グリッドの絵コンテ（リード表）**: `timeline.json` を先に書き、小節ごとに「画面・観客に理解させること（リード）・テロップ・カメラ・SE・音楽の状態・抜け方」を表にする（brief-template の §6）。**コードを書く前に、全タイミングが拍の上にある表を作る**（研究:opus-video-prompts, anim-base）。
5. **キーフレームのスチル**: 本番の描画コードで、6〜10 時刻のスチルを出して見る（`render.mjs --still`）。1枚ずつポスターとして成立するか（構図・階層・余白・組版・セーフマージン）を見て、テンプレ臭さ・窮屈さが消えるまで直す（研究:mg-styles-15）。モックアップでは確認しない（研究:lemo-opuscar）。
6. **一番難しい 2〜4 秒だけ先に動画にする**: ヒーローモーメントか最速の転換。隣接 12〜24 コマのストリップ、順不同で描いて一致するか、音と字幕の同期を確認する（研究:awesome-athemeroy）。ここで直せないものは本番でも直らない。
7. **全尺レンダー**: 下書きはブラーなし・半解像度でもよい。本番は速い区間だけサブフレームブラー（§4.4）。`master.py` で音と合体して QC。
   - 速度の目安: 1080×1920・30fps は 1秒あたり約7秒でレンダリングできる（15秒で約105秒、1プロセス）。長尺は `--from` で分割して並列化を検討（既存ルール）。`render.mjs --workers N` の並列化を使う（道具: 更新中）。ブラーはサブフレーム数に比例して遅くなるので、区間を限る。
8. **審査（別エージェント）**: 作っていないエージェント（Agent ツールのサブエージェント、または別セッション）に、完成 mp4・レビュー用シート（§9）・brief の「目的・シグネチャ・合格ライン」・`rubric.md` だけを渡す。**作り手の説明や修正ログは渡さない**（研究:mg-styles-15, awesome-yihui）。審査は JSON で返させる。
9. **修正は1ラウンドにまとめる**: 審査の修正リストを影響の大きい順に全部まとめて直し、もう一度だけ審査する。審査で長所とされた点を壊さない。直す前の版は `vN/` に残す（研究:lemo-opuscar, mg-styles-15）。
10. **最終**: 合格ラインを満たせば公開。満たさなければ次のテイクとして 7〜9 をくり返す（SKILL の最大5テイク内）。残った弱点は報告書に1行ずつ正直に書く。

**記録すること**（報告書の数値）: テイク数、審査ラウンド数と各回の平均点、レンダー時間、尺・LUFS・TP、使った曲と区間、権利ログ、費用（モデル呼び出し・外部サービス・人の作業を分ける）（研究:awesome-athemeroy）。

## 3. 演出ルール

### 3.1 構成
- **最初の 0.5〜3 秒でフック**。SNS は 0.5 秒、30 秒以上の作品でも 3 秒以内。ロゴがゆっくり出てくるだけの冒頭は不可（研究:lemo-opuscar, mg-styles-15）（R001 と同旨）。
- **1被写体・1目的・1ターン**。サムネイルの大きさで読めるネタ1つは、読めないネタ3つに勝つ（研究:lemo-opuscar）。
- **ヒーローモーメントは尺の 60〜75% に1つ**。誰が見ても分かる大きさで。その媒体にしかできない動き（ネイティブムーブ）をここに置く（研究:mg-styles-15, lemo-opuscar）。15秒なら 9.0〜11.25 秒、6秒なら 3.6〜4.5 秒。
- **エンド画は 0.8〜1.2 秒ホールド**。止めずに微動（星のまたたき、ゆっくりしたプッシュ）を残す。ロゴ・CTA はこの間に読める（研究:mg-styles-15）。
- **結末は冒頭と韻を踏む**: 同じ位置・同じモチーフを、変化させて出す（研究:lemo-opuscar, anim-base）。
- **緩急**: 明確な加速か減速を1回、息をつくホールドを1回入れる。一定の速さの映像は失敗（研究:lemo-opuscar）。
- **反復部はエスカレートさせる**: 同じ型の場面を何度か出すなら、毎回1段強くする。全体を1本のモチーフでつなぐ（研究:pdoom-mexicat, pdoom-heibel）。
- **同じテンプレートの焼き直し禁止**: 構成・冒頭・看板ショット・カメラ経路・音楽の形・結末の6項目のうち、4項目以上を前作と変える。自動量産のときは前作のコンタクトシートと並べて確認する（研究:lemo-opuscar）。

### 3.2 リード（観客が理解すること）とタイミング
- 観客は内容を知らず、等速で一度だけ見る。ショットごとに「観客が理解すべきこと」を順番に書き、それぞれに「目が見つける時間＋理解する時間＋定着する一瞬」を与える（研究:anim-base）。
- **一度に1つのことだけ**。同時に2つ起きると片方しか見られない。原因→反応は重ねず順番に置く。反応に時間を与える。
- 重要なリードの直前に、動き・明るさ・大きさで目をそこへ運ぶ。
- **リードの数がショットの長さを決める**。15〜30秒の縦動画は1ショットにリード2〜3個まで（研究:anim-base）。
- 動作は速く、意味はホールドで伝える。予備動作があれば動作は速くてよい。

### 3.3 カメラの語彙
- 1作品で使うカメラ操作を先に決め、それ以外は使わない。それぞれに「なぜそう動くか」を書く（研究:awesome-yihui）。
- 種類の目安: 15秒以下は3種類、30秒以上は4種類以上（研究:lemo-opuscar）。
- 語彙: スロープッシュ（ショット内で 1.03〜1.07 倍。止まって見えるコマをなくす）／プルバック（スケールを明かす。ズームは対数空間で補間）／パン・トラック（被写体に追従）／ホイップ（必ずモーションブラー付き）／ロール（意図して1回だけ）／速度合わせ（動く被写体と同じ速さで動いて止めて見せる）／パララックス（2.5D の層ごとの奥行き）／フォーカス送り／額縁構図（研究:awesome-yihui, lemo-opuscar）。
- 要所では主被写体を画面の高さの 1/3 以上に（研究:lemo-opuscar）。キャラが踊る・見せ場では約 40%（研究:pdoom-heibel）。
- 追従する効果（スポットライト・枠・ラベル）は、ワールド→スクリーン変換の関数を1つにまとめて通す。そうしないとカメラ移動後に被写体からずれる（研究:lemo-opuscar）。
- 光の演出は `globalCompositeOperation='lighter'` の放射グラデーションと回折スパイクで作ると安っぽくならない（R001）。

### 3.4 転換とカット
- **転換は画面の中の要素に運ばせる**: 色面ワイプ・形のアイリス・マッチカット・物が画面外へ抜けてカットを運ぶ・線が次の絵になる。既定のクロスフェードと素のカットは避ける（意図したスマッシュカット・アクションつなぎは可）（研究:lemo-opuscar, mg-styles-15）。
- 毎回同じ転換にしない。全ての継ぎ目（入り・ショット間・出）に転換を設計する（研究:anim-base）。
- カットをまたいで運ぶ物は、カットの前後で同じピクセル位置に置く。マッチカットの座標は実行時に計測する（研究:opus-video-prompts）。
- **消えるのもデザインする**: 細線が横切って潰れる・点に潰れる・1拍に1パーツずつ畳む。フェードに逃げない（研究:lemo-opuscar）。
- カットは小節頭、要素の出現は拍頭が基本（既存ルール）。毎拍カットはしない（研究:lemo-opuscar）。
- トランジション中の空白フレーム（何も映らないコマ）を作らない（研究:lemo-opuscar）。

### 3.5 禁止リスト（スタイルが求める場合だけ例外。例: シンセウェーブのグリッド床とネオン）
パーティクルの爆発、汎用のグロー・ネオン、レンズフレア、RGBずれ、意味のないカメラシェイク、グリッドの床、点滅する背景、すべてフェードイン、等速移動、弾みすぎるイージング、紫×シアンのネオン、光る脳、コードの雨、AI っぽいストック風の絵、テンプレっぽい見た目、0.5秒を超える意図しない停止、**偽の数値・偽のレビュー・偽の実績**（研究:opus-video-prompts, pdoom-mexicat, awesome-yihui）。

### 3.6 よくある失敗（見つけたら直す）
被写体が小さすぎる・端に寄りすぎる／暗すぎる、同系色の重ね（赤の上に赤、青の上に黄で濁る）／字幕が被写体を隠す／ネタが速すぎて伝わらない／何も起きていない区間／顔や状態がパッと切り替わる（必ず補間する）／全パーツが同時・同じカーブ・同じ量で動く（機械的）／看板やラベルで物語を説明してしまう（研究:lemo-opuscar, anim-base）。

## 4. モーション

### 4.1 決定性（全作品の前提）
- ページは `window.renderAt(t)` で時刻 t の絵を**決定論的に**描く。乱数はシード付きにする（既存ルール）。
- 具体的には: `Math.random()`・`Date.now()`・`performance.now()` を使わない。乱数は `hash(i)`／`mulberry32(seed)`。CSS transition とタイマーを使わない（CSS/WAAPI アニメは pause して currentTime でシークする場合だけ可）。フレームをまたいで状態を持たない。物理やパーティクルは閉形式か事前計算（研究:mg-styles-15, opus-video-prompts, anim-base）。
- フレーム単位で変わるもの（ちらつき・ボイル・グレインのシード）は `frameIdx = Math.round(t*fps)` で決める。`floor` だとブラーのサブフレームが2状態にまたがって二重に写る（研究:pdoom-mexicat）。
- 実写・連番素材は `<video>` のシークを使わず、事前に表示サイズの JPEG 連番にして `floor((t-t0)*fps)` 番目を引く。`renderAt` は画像のデコードを await してよい（研究:lemo-opuscar）。
- 決定性の検査: 同じ t を逆順・ランダム順で2回描き、ピクセル差ゼロを確認（§1）。
- Canvas で使う Web フォントは `window.__ready` 内で `document.fonts.load('700 34px "Font"')` して事前に読み込む。DOM で使っていない書体は読み込まれず、明朝体に化ける（R001）。

### 4.2 イージングとばね（`motion.js` に入れる予定の定番）（道具: 予定）
- 等速は使わない（機械表現のときだけ可）。素の lerp には必ずイージングを通す（研究:mg-styles-15, anim-base）。
- 定番カーブ: 弾む入場 `cubic-bezier(0.34,1.56,0.64,1)`／移動・線描 `(0.65,0,0.35,1)`／精密スナップ `(0.7,0,0.2,1)`／液体 `(0.22,1,0.36,1)`／バウハウス系はオーバーシュートなしの inOut（研究:mg-styles-15, lemo-opuscar）。スイス系は全編1本のカーブに統一する。
- **臨界減衰ばね**: `x = 1-(1+ωu)e^(-ωu)`（u=t-t0、ω=12〜40）。行き過ぎず「速く着いて柔らかく止まる」。UI・ロゴ向き（研究:awesome-yihui）。
- **減衰振動ばね**: `x = 1-e^(-ζωu)(cos(ω_d u)+(ζω/ω_d)sin(ω_d u))`、f=2〜3Hz、ζ≈0.4。ポップ用。着地から約0.9秒後に値を 1 にピン留めして、ズーム中のサブピクセルの漂いを止める（研究:mg-styles-15）。
- **ばねの和**: 目標が何度も変わる値は「変化ごとのばねの和」で書く。`v = v0 + Σ(to_i - to_{i-1})·spring(t - t_i)`。t の純関数のまま途中の目標変更が滑らかになる（研究:opus-video-prompts, mg-styles-15）。
- 伸縮する物（タブの下線・トグル）は、両端を違う周波数のばねに乗せる。進む側が先に伸び、後ろが追いつく（研究:opus-video-prompts）。
- 速度に比例したスクワッシュ＆ストレッチ（約10%、体積を保つ: 横 1+k・縦 1-k）。重い物は動き出しも止まりも遅く跳ねない、軽い物はパッと動いて跳ねる（研究:mg-styles-15, anim-base）。

### 4.3 拍に着地させる
- **動きは拍の少し前に始めて、拍で着地させる**。目安は 0.05 秒前（研究:awesome-yihui）。スナップは1音価前（既定は8分音符）から始める（研究:lemo-opuscar）。
- 開く・広がる動きは1フレーム早く始め、拍のフレームで既に約80% 開いているようにする（研究:lemo-opuscar）。
- 尺は秒でなく音価（8分・16分）で指定する。キュー時刻はフレーム境界に丸める（`Math.round(t*fps)/fps`）。フレームの間に落ちる出現はちらつく（研究:lemo-opuscar）。
- 加速はテンポを変えず拍の分割で作る（4分→8分→16分）（研究:lemo-opuscar）。
- **スタッガー**: 2〜4 フレームずらす。後半ほど詰めるなら `lerp(a, b, 1-cbrt(1-i/n))`（研究:mg-styles-15）。同時に主役として動くのは1つだけ。
- 左右対称・同時の動き（ツイニング）を避ける。片腕だけ・群衆は位相をずらす。目が先、体が後、付属物が遅れて行き過ぎて収まる（研究:anim-base）。
- 入れ物（図形）が変形し始めてから中身が入り、次の変形の前に中身が出る。文字を重ねない（研究:opus-video-prompts）。

### 4.4 サブフレームのモーションブラー（道具: render.mjs --blur / --shutter、更新中）
- 1フレームを N 枚のサブフレームの平均にする。シャッター 180°（半フレーム）。サブフレーム s の時刻は `(f + 0.5*((s+0.5)/N - 0.5))/fps`（研究:mg-styles-15）。
- 速い区間（ホイップ・スラム・転換）だけ N=4〜8。静止区間は1回だけ描いてコストを抑える（研究:lemo-opuscar, pdoom-mexicat）。
- サンプルがカットをまたがないようにする（またぐサンプルは捨てる）。カウンター・数字・いま読ませる文字は**フレームの時刻**を読み、ブラーさせない（研究:lemo-opuscar, awesome-yihui）。
- 下書きは N=1・半解像度、本番だけ N を上げる（研究:opus-video-prompts）。

### 4.5 カメラ・キャラ・ループの数式
- カメラパスのキーは単調3次補間（Fritsch–Carlson）。キーの間で行き過ぎないのでカメラが揺り戻さない（研究:lemo-opuscar）。
- ズームは `exp(lerp(log(za), log(zb), e))`。対数で補間すると等速に見える（研究:mg-styles-15）。
- 2.5D: 層の高さ z ごとに `s = 1/(1/zoom - z)` で拡大すると、手前ほど大きく速く動く（研究:lemo-opuscar）。
- キャラは2コマ打ち（12fps）、カメラと光は毎フレーム滑らかに。段々に動くカメラは遅延に見える（研究:lemo-opuscar）。手描きの線の揺れ（ボイル）は 12回/秒で、パーツごとに別シード（研究:anim-base）。
- ループ: 小さな動きはすべて周期関数にし、周期をループ長の約数にする。物ごとに位相を変える。最終フレームの次＝最初のフレーム（カーソルの位置と速度も含む）（研究:lemo-opuscar, opus-video-prompts）。

### 4.6 数字
- 数字は固定幅（tabular-nums、または '0' の幅で1字ずつ中央揃え）。ロール中に桁が揺れない（研究:lemo-opuscar）。
- カウントアップはフレームに量子化した時刻で計算し、`easeOutCubic`。節目で 6% のスケールパンチ（研究:mg-styles-15）。
- 数字ロールは 3〜5 フレーム乱数が跳ねてから実値に落ちる。スクランブルは 16分音符ごとに1桁ずつロック。衝撃のフレームでは読める数字だけを出し、デコードは次のフレームから（研究:mg-styles-15, lemo-opuscar）。
- グラフの棒は値に正確に比例させる（研究:mg-styles-15）。

### 4.7 ハマりどころ
- カメラで拡縮する要素に `will-change` を付けると文字がぼける。`preserve-3d` の要素に opacity/filter を付けると平面化する（ラッパーをフェードする）（研究:opus-video-prompts）。
- 大見出し（230px 前後）は 1080px 幅だと5文字で溢れる。`scrollWidth` を見て自動縮小する（R001）。
- グレインをページで描くと毎フレーム圧縮が効かず、レンダーも遅い。グレインは ffmpeg で後付け（§6）（研究:lemo-opuscar）。

## 5. タイポグラフィとテロップ

### 5.1 共通
- 書体は2種類まで、理由を1行で書く。ウェイトと字間まで指定する（研究:awesome-yihui）。和文は OFL のもの（Noto Sans JP、Zen Kaku Gothic、Shippori Mincho、M PLUS Rounded など）。
- 画面の文字に句点「。」を付けない（研究:opus-video-prompts）。約物は組版用（「」『』…—）。
- 縦型は1行 14 字以内・2行まで。改行位置と禁則は手で決める。1言語1行で、意図しない折り返しは不可（研究:mg-styles-15, lemo-opuscar）。
- 縦 9:16 は横 16:9 の切り抜きではなく、別レイアウトとして組む（研究:lemo-opuscar）。ページは `innerWidth/innerHeight` 基準で組み、比率ごとにレイアウトだけ切り替える。
- 見出しの型: 「色チップ＋番号＋和文見出し＋英字の小見出し（字間 0.18em、グレー）」の4要素で統一すると整う（研究:mg-styles-15）。

### 5.2 可読時間（ゲート）
- **テロップ1枚の表示時間 ≥ max(1.8秒, 読む時間＋0.6秒)**（研究:lemo-opuscar）。
  - 読む時間 = ナレーションがあれば発話時間。なければ 文字数 ÷ 8 秒（日本語の黙読の目安。暫定値なので実制作で検証する）。記事・ノウハウなど理解が要る情報テロップは 文字数 ÷ 6 秒で計算する。
- 速く見せたいときは、読み終わる前に切るのではなく、1画面の文字を減らす（研究:lemo-opuscar）。
- 字幕の時計はショットの長さではなく読む時間で決める。ショットが 1.5 秒で変わっても、字幕は読み終わるまで残す（研究:lemo-opuscar）。
- 声と同期する字幕・カラオケは、声より先に点灯しない。先読みとして最大 0.4 秒前から 30〜40% の濃さで見せるのは可（研究:pdoom-mexicat）。
- 自動検査として、ページが `window.TEXTS(t)`（その時点の全テキストと矩形）を返し、表示時間を集計する（道具: 予定）（研究:lemo-opuscar）。

### 5.3 キャプション・ニュース文法（記事→SNS、告知）（研究:lemo-opuscar）
- テロップは `"接近|年初の|{半分}"` のように、`|` でチャンクに区切り、`{}` でキーワードを指定してタイムラインに持つ。ページ・.srt・音が同じデータを読む。
- 各チャンクは前のチャンクの 0.12 秒後に入る。スケール 1.3→1 を 0.13 秒（back、オーバーシュート強め）、不透明度は 0.04 秒で全開。
- キーワード1語に色ブロックが 0.12 秒で左から右へワイプし、文字は反転色になる。
- 冒頭は最大の数字を4フレーム目に着地させ、0.45 秒で値までロールさせる。数字には出典タグを付ける。
- 音なしで意味が通じる構造にする（SNS の自動再生は無音が多い）。

### 5.4 バラエティ・テロップ文法（SNS 縦、楽しい系）（研究:mg-styles-15）
- 重ね順: 押し出しの影×2 → 色付きの外ストローク → 白ストローク → グラデーションの塗り → 光沢。Canvas は strokeText を太い順に重ね、`lineJoin='round'`。
- 1文字ずつばねで弾む: スケール 0→1.15→1（約8フレーム）、2フレームずつずらす。上から落ちる・回転しながら入るを混ぜる。
- 着地後は止めずに小さく揺らす（回転 ±2°・上下 ±3px・約1.1Hz、文字ごとに位相を変える）。
- 効果音が先、文字は 2〜3 フレーム遅れて出る。
- 感情の型: 驚き＝放射線・爆発枠／ツッコミ＝斜めの手書き風／気まずさ＝汗マーク／嬉しい＝キラキラ。枠や記号はシード付きで生成する。
- 一度に出すテロップは1つ。強調語だけ大きく・色を変える。安全域（§1）を守る。

### 5.5 ロゴ・CTA
- ロゴは冒頭と末尾。ブランド色は地色ではなくアクセントに使う（研究:lemo-opuscar）。
- ロゴ着地後 1.0 秒以上は読める状態を保つ。CTA の文言も §5.2 のゲートを満たす。
- 製品名・社名を TTS に単独で読ませない（聞き間違えられる）。数字は読みで書く（研究:lemo-opuscar）。

## 6. 色と仕上げ

- **パレットは HEX で 3〜5 色、アクセントは1色**。色ごとに画面の占有率の目安も書く（例: 地色 70%・アクセント 10% 以下）（研究:lemo-opuscar, awesome-yihui）。
- 広告は「無彩色ベース＋アクセント1色」が主流（色のある画素の割合の中央値 17.6%）。色を足したくなったら、まず減らす（研究:awesome-athemeroy）。
- 発光してよい（ブルームをかけてよい）のはアクセント色だけ（研究:pdoom-mexicat）。純黒・純白は避け、インク色とクリーム色を使う（研究:anim-base）。
- 背景の明るさ・主色・アクセント・ショット間の色の一貫性まで指定する。「モーショングラフィックスで」だけでは色が決まらない（研究:awesome-athemeroy）。ダーク版とライト版のプリセットを用意する。
- 明暗のリズム: 何場面かは地と図を反転させる（紙地にインクの線）（研究:pdoom-mexicat）。
- 光で開示する（ロゴ・製品）: 光の帯が通った部分だけ見せ、未通過は明度 7% 程度で敷く。帯の先頭のハイライトは 20% 以下、1.3 秒以内に開き切る（研究:lemo-opuscar）。
- 仕上げの順: ハイライトの肩（0.82 を超える分を圧縮）→ 軽いビネット → グレイン（中間調ほど強く）→ 三角分布ディザ（±1/255。グラデのバンディング対策）（研究:mg-styles-15）。
- **グレインは ffmpeg で後付け**（`noise=c0s=2〜4:allf=t`）。ページで描かない。ピクセル・ベクター系は 0、明るい地では弱く。グレインを乗せたら x264 に `-tune grain` と `aq-mode=3`（研究:lemo-opuscar, pdoom-mexicat）（道具: 予定）。
- Chrome は `--force-color-profile=srgb --font-render-hinting=none --disable-lcd-text` で起動する（render.mjs は対応済み）（研究:mg-styles-15）。
- 書き出しは BT.709 タグ（§1）。マスターは高画質で残し、SNS 配信用は 8〜12Mb/s、Web 埋め込み用は別に再エンコードする（研究:mg-styles-15）。
- 写真・実写のグレードを1つに揃える（例: コントラスト +7%・彩度 -8%・暖色を 6% 重ねる）。拡大の上限は 現代の映像 1.5 倍・写真 1 倍（研究:lemo-opuscar）。
- 3D や写真を入れたら、レンダー結果の画素を測ってブランド色とのずれを補正する（研究:awesome-yihui）。

## 7. 音

### 7.1 タイムラインを唯一の情報源にする
- **`timeline.json` を最上流に置き、絵・音楽・SE・テロップがすべてそこを読む**（研究:lemo-opuscar, mg-styles-15）。中身: `fps, bpm, bars, sections[], K{キーポイント}, hits[], cam[], caps[], sfx[]`。音側の都合でずらすのは禁止で、合わないときは絵のキーを拍に寄せる（研究:mg-styles-15）。
- 合成 BGM は拍・小節・各楽器の発音時刻が正確に分かるので、解析せずにそのまま出力する（研究:pdoom-mexicat）。現状は `bgm.py` が `*.beats.json` を出し、`render.mjs --data` で `__DATA.bar_sec` / `beat_sec` / `cues` として読める（既存ルール）。
- 絵の側から音のイベント（`window.EV`）を出し、SE を配置する。音楽のヒット・絵のイベント・実際のオンセットを突き合わせ、ズレを ms で表にする（道具: 予定）（研究:lemo-opuscar）。
- カット点は時刻を直書きせず、内容（歌詞・テロップ・セクション）から求めて拍に吸着させる: 「その語の手前の拍」「最寄りの小節頭」（研究:pdoom-mexicat）。

### 7.2 曲の選び方: ライブラリ曲か、合成 BGM か
| | ライブラリ曲（ユーザー提供の SUNO 自作曲 15 曲。和太鼓・箏・エピック。`studio/music-library/`） | 合成 BGM（`bgm.py`） |
|---|---|---|
| 向く用途 | ショーリール、和・ダークファンタジー・舞台系の世界観、編集力（曲に合わせたカット）を見せる作品 | 尺ちょうど（15.000秒など）が必要な広告、明るいトーン、記事動画のトーン切り替え、サウンドロゴ、サイネージ |
| 尺 | 曲の小節に合わせて映像側の尺を決める（n 小節 × 曲の小節長） | 尺から BPM と小節数を決める（例: 128 BPM × 8 小節 = 15.0 秒） |
| 同期の基準 | `analyze_audio.py` の `downbeats[]` / `beats[]`（実測） | `*.beats.json`（正確） |
| 注意 | 権利・公開範囲を rights log に記録。舞台案件の劇伴かどうかとユーザーの公開許可を確認（SKILL のガードレール） | 低域の盛りすぎ（§7.4） |

### 7.3 ライブラリ曲の使い方
- まず `analyze_audio.py` の JSON（BPM・拍・小節頭・キー・セクション・エネルギー・推奨カット）とスペクトログラム PNG を見る。
- **BPM の表示値を信用しすぎない**: 解析は約 43fps のフレーム単位でテンポを量子化するので、107.7 / 103.4 / 129.2 / 83.4 のような値に丸まり、±1〜2% ずれることがある。15 秒で最大約 0.3 秒ずれる。秒の計算は `bpm × n` ではなく `beats[]` / `downbeats[]` の実測時刻を使い、使う区間だけ拍をオンセットに再フィットする。倍・半分のテンポの取り違えも確認する（研究:pdoom-mexicat, pdoom-heibel）。
- 耳で決めたテンポは系統的にずれる（3:2 で拍頭と裏拍に交互に落ちる例があった）。テンポは測るか、合成して既知にする（研究:pdoom-heibel）。
- **切り出しは小節線で**: 開始は小節頭（アウフタクトがあるなら1拍前から）。**終わりはセクション境界かエネルギーの谷**に置き、最後の音の余韻を 0.3〜0.8 秒残してからフェードする。曲の途中でぶつ切りにしない。
- 映像のカットは曲の `downbeats[]` に、要素の出現は `beats[]` に置く。曲のアクセント（太鼓の一打）を見つけてヒーローモーメントに当てる。
- 曲のキー（解析の `key`）に合わせて SE の音程を選ぶ。和太鼓系の曲には金属的なきらめき音を重ねすぎない。
- ライブラリ曲はラウドネスがばらつく（-26〜-11 LUFS）。master.py の loudnorm で -14 に揃える。

### 7.4 合成 BGM（bgm.py）
- 外部音源は使わず、すべて数値合成。曲の設計は `song.json`（BPM・キー・コード進行・セクション・メロディ・キュー）（既存ルール）。
- 15秒広告の型: 128 BPM × 8小節 = 15.0 秒ちょうど。イントロ2小節 → 本編4小節 → ロゴ2小節（stab + chime）（R001）。
- スマホのスピーカー前提で低域を盛りすぎない。サブベースは入れない、パッドは 160Hz でハイパス、キックの減衰は短め（R001）。帯域の目安は §1（+6dB 以内。R001 は +8dB で重かった）。
- 追加の目安: 20〜120Hz は他の帯域より約 -3dB。パッドは MIDI 48 未満の音を使わない。ベースに2次・3次倍音を足して小型スピーカーでも聞こえるようにする（店頭サイネージで特に重要）（研究:lemo-opuscar）。
- 120Hz 以下はモノラルにまとめ、広げるのは M/S だけ（ハース効果は使わない。スマホはモノ再生が多い）（研究:mg-styles-15）。
- キューの種類: `riser`（盛り上げ）、`impact`（ドロップ）、`stab`（ロゴ着地）、`chime`（場面転換・きらめき）。映像の大きな切り替わりにはキューを置く（既存ルール）。
- 曲の形は「ドロップ＝小節0」に合わせてイントロ→ビルド→ドロップ→アウトロを組む（研究:mg-styles-15）。
- ドロップの直前は残響も切って完全な無音にし、逆再生の whoosh だけ置く。ドロップのピークを約 3dB リミットしておく（しないと loudnorm が dynamic モードに落ちて目標から外れる）（研究:lemo-opuscar）。
- サウンドロゴ: 4音の短いモチーフを最初に鳴らし、ドロップで1音ずつ応答させ、ロゴで主音に解決させる（研究:mg-styles-15）。
- ありがちな「ピアノとストリングス」は避ける（研究:lemo-opuscar）。

### 7.5 SE（効果音）の置き方
- **SE は sync point をイベント時刻に置く**。sync point は、衝撃・クリック＝トランジェント、whoosh＝通過のピーク、riser・逆再生シンバル・チャージ＝終端（＝ヒット）。ファイルの先頭ではなく実測ピークで合わせる（研究:mg-styles-15, opus-video-prompts）。
- **1フレーム早めに置く**と、トランジェントがヒットのフレームで「鳴って見える」（研究:mg-styles-15）。
- 意味のある見える動作には音を付ける。素材ごとに音色を変える（紙・木・金属・ガラス）（研究:lemo-opuscar）。広告では、シーン転換ごとにソフトな whoosh 1つ、クリック音は画面上の実際の操作にだけ（研究:awesome-yihui）。
- 1フレームに重ねる SE は 3 個まで。whoosh の長さは画面上の移動時間に合わせる。繰り返す UI 音は音程とシードを変え、曲のキーに合わせ、物の位置にパンする（研究:mg-styles-15）。
- ヒーローのヒットは impact＋低いブームを重ね、riser で導入する（研究:mg-styles-15）。
- レベル: SE は知覚レベルを揃えてから置き、gain は意図（控えめ -6dB、ヒーロー +2dB）にだけ使う（研究:mg-styles-15）。

### 7.6 ミックスとマスター
- ダッキング: SE の sync point の前後で音楽を 3dB 下げる。ナレーションの下では音楽を 8〜11dB、SE を 4〜6dB 下げる。ピークホールド（0.12秒）→平滑化（0.08秒）で滑らかに（研究:mg-styles-15, lemo-opuscar）。
- ナレーションはコンプをかけ、RMS で音楽より約 10dB 上（研究:lemo-opuscar）。
- **本当の無音**: 30秒以上の作品は2回、短尺は1回。無音明けの最初の音を、作品で最も重要な音の1つにする（研究:lemo-opuscar）。無音はデジタルゼロ。
- **J/L カット**: 次の場面の音を 0.3 秒早く入れる（J）、前の場面の余韻を次へ残す（L）。30秒以上は2回、短尺は1回（研究:lemo-opuscar）。
- マスター: 28Hz ハイパス → 120Hz 以下モノ化 → 軽いグルーコンプ → トゥルーピークリミッタ（オーバーサンプリングで再検証）→ 2パス loudnorm → 4ms フェードイン・末尾フェード（研究:mg-styles-15, lemo-opuscar）。
- 音声が映像より短いときは無音で埋める（apad）（研究:lemo-opuscar）。
- 音楽だけのステムも書き出しておく（差し替え・再編集用）（研究:awesome-yihui）。
- 音を聴けない前提で、数値（帯域別エネルギー・ラウドネス・LR相関・オンセットのズレ）とスペクトログラム画像（cue の印付き）で評価する（既存ルール＋研究:mg-styles-15）。

## 8. 用途別の型

### 8.1 SNS 広告 15 秒（縦 1080×1920・30fps）
- 128 BPM × 8 小節（1小節 1.875 秒）（R001）。
- 小節1: フック（フレーム0から完成した絵。キーワードが拍ごとに1語ずつ着地）／小節2〜5: 1小節1メッセージ／小節6頭（9.375秒 = 62.5%）: ヒーローモーメント。直前の半拍は無音／小節7: CTA／小節8: ロゴ着地（stab＋chime）、エンド画 1.2 秒ホールド。
- カメラ3種、無音1回、J/L カット1回。テロップは1小節1枚で、§5.2 のゲートを満たす文字数にする（1.875 秒なら約9字まで）。
- ライブラリ曲で作る場合は、曲の8小節（BPM により 14〜16 秒）に映像を合わせ、終わりをセクション境界に置く。

### 8.2 6 秒バンパー
- 120 BPM × 3 小節 = 6.0 秒。メッセージは1つだけ。
- 0〜0.5 秒でブランドか問いを見せる → 4.0 秒（67%、小節3頭）にヒーロー（ロゴ着地や変形の決め）→ 5.0〜6.0 秒ホールド。
- テロップは2枚まで。音は stab かサウンドロゴで締める。

### 8.3 店頭サイネージのループ（横・縦両方）
- **音なしで成立させる**（店頭は無音か騒がしい）。テロップだけで意味が通る。
- ループ長は 15 秒か 30 秒（128 BPM × 16 小節 = 30.0 秒）。最終フレームの次＝最初のフレーム（継ぎ目ゼロ）。小さな動きは周期関数で、周期をループ長の約数にする。
- 離れて見るので文字を大きく（短辺の 8% 以上を目安）、1画面1メッセージ、ホールドを長めに（各 3 秒以上）。速い点滅・強いフラッシュは使わない。
- 音を付ける場合は低域を控え、ベースに倍音を足す（§7.4）。

### 8.4 記事→SNS 動画（自動投稿）
- **数字・固有名詞・引用は `facts.json`（出典URL付き）にだけ書き、テンプレートは `{{slot}}` で参照する。ハードコードした数字はレンダー前の検査で差し戻す**（研究:awesome-athemeroy, awesome-yihui）。facts に無い主張・数字・実績は出さない。素材が足りなければ止まって報告する（偽の素材で埋めない）。
- 構成: フック（記事で一番強い数字か問い、4フレーム目に着地）→ 要点 3〜5（1ショット1事実、逆ピラミッド）→ 中盤にターン（意外な点）1つ → まとめと CTA。テロップは記事本文から引用し、言い換えで意味を変えない（研究:lemo-opuscar, awesome-yihui）。
- 文法はキャプション・ニュース（§5.3）。120 BPM の半拍グリッドでカット。テロップの切り替えは 2.5 秒より速くしない。
- 記事のトーン（告知 / ノウハウ / 実績紹介 / 季節ネタ）で、色・テンポ・BGMジャンル・テロップ量を切り替える（既存ルール）。スタイルの組み合わせは `styles.md`。
- 9:16（主）と 1:1 は別レイアウト。ナレーションを付けるなら、字幕とナレーションを同じタイムラインから作る。
- 投稿文は 1 行目で要点。ハッシュタグは 2〜3 個まで。X 投稿は 1 日 3 件まで。投稿URLは管理アプリに記録（既存ルール）。

### 8.5 ショーリール（動画編集の実力を示す）
- 30〜60 秒。章ごとにスタイルを変えてよいが、**パレット・書体・1本のモチーフ（例: 天狼星の光の線）で束ねる**。モチーフが章をつないで最後に回収される（研究:pdoom-mexicat）。
- 編集技術を見せる場面を意図して入れる: 曲の小節線に合わせたカット、マッチカット、J/L カット、速度ランプ（意味のある小節で）、色の統一、テロップの組み込み方の変化（研究:lemo-opuscar, pdoom-mexicat）。
- 音楽はライブラリ曲を基本にし、章の切り替えをセクション境界に置く。曲の盛り上がりで最強の章を見せる。
- 他社のデモ映像は使わない。自社で作ったものだけで構成する（研究:lemo-opuscar, mg-styles-15）。

### 8.6 Web ヒーローのループ
- 8〜12 秒の継ぎ目ゼロのループ。動きは遅く小さく、上に載る見出しの読みやすさを壊さない（背景のコントラストを抑える）。
- 全モーションを周期関数にし、物ごとに位相を変える（研究:lemo-opuscar）。
- 軽量に書き出す（数 MB 以内を目安）。ポスター画像を用意し、`prefers-reduced-motion` ではポスターだけを出す。

### 8.7 データ・統計
- 数字は §4.6。棒は値に正確に比例。数字には出典。1画面に巨大な数字は1つで、キャプションを重ねない（研究:lemo-opuscar）。
- 数値を音程やリズムに写して「数字が鳴る」演出も使える（絵と音が同じデータを読む）（研究:lemo-opuscar）。

### 8.8 HP制作（用途別サンプル）
- スマホ幅 390px を先に作り、1440px に広げる。Playwright で両方のスクショを撮って目視（既存ルール）。
- 目標: Lighthouse モバイル Performance / Accessibility / SEO 90 以上。画像は WebP、幅指定、`loading="lazy"`、`alt` 必須（既存ルール）。
- 架空店舗のサンプルであることをフッターに明記する（実在店と誤認させない）（既存ルール）。
- 業種ごとのスタイルはスタイルカード（`styles.md`）で管理し、ヒーローにはループ動画（§8.6）を使う。

## 9. レビューの手順

見なければ品質は上がらない。コードを読んでも動きは見えない（研究:anim-base）。画像は必ず Read で開いて見る。

1. **数値チェック**（先に機械で落とす）: 尺・解像度・fps・色タグ（ffprobe）、LUFS・TP（ebur128）、黒味・無音（master.py --qc）、静止区間（フレーム差分）、決定性（同じ t を順不同で2回）、ループの継ぎ目、cue とオンセットのズレ、可読時間、帯域バランス、ステレオ相関。
2. **拍ごとのコンタクトシート**: 1拍1コマを並べる（道具: 予定）。拍に乗っているか、毎拍何かが起きているかを見る。加えて 0.5 秒ごとのシートで全体の形を見る。1秒間隔のシートだけだと遷移の瞬間を見逃す（R001）。
3. **カット前後のストリップ**: 各カット・転換の ±0.5 秒の全フレーム、またはカットの直前と直後の各1フレーム。空白フレーム・ずれ・ポップを探す（研究:pdoom-mexicat, anim-base）。
4. **重要な動きの 0.1〜0.2 秒刻み**: ヒーローモーメント、最速の動き。予備動作・フォロースルー・等速・左右対称を見る（研究:lemo-opuscar, anim-base）。
5. **等倍のクロップ**: 文字のエッジ、細線のちらつき、グラデのバンディング、ロゴ、顔（研究:anim-base, mg-styles-15）。
6. **観客として読む**: 0.1〜0.15 秒刻みのシートを順に読み、各リードが何フレームもらえているか数える（研究:anim-base）。
7. 要所の静止画は `--still 秒:ファイル,...` で出し、横に並べて（`convert +append`）1枚で目視する（R001）。
8. **予算**: 1ショットに最低1シート、重要な動きと転換ごとに1ストリップ、物語を担う顔・ロゴごとに1クロップ（研究:anim-base）。
9. 審査エージェントには、1〜6 の画像と数値を渡す（§2 の手順8、`rubric.md`）。

## 9.5 制作から学んだこと（実績）

### 3D（天狼シネマ）の基盤（P016 / R004）
- 部品は `tools/cine/cine.js`（createStage・stageFloor・spot・beam・dust・材質プリセット）。ページは importmap で `/node_modules/three/...` を読む。render.mjs が studio/ をローカル HTTP で配信するので ES モジュールが使える。
- 環境は GPU なし（SwiftShader）。1080×1920・DOF＋ブルーム付きで 1フレーム約3.9秒、3並列で実効 1.4秒/フレーム（15秒≒10分）。静止画確認は 1枚約2秒なので、キーフレームで詰めてから全尺に進む。
- 暗転を本当の黒にするには、環境反射（`scene.environmentIntensity`）も照明と一緒に 0 にする。RoomEnvironment は明るいので 0.06 以下。
- 地平線のグレーの帯は `FogExp2(黒, 0.16)` で床の奥を溶かして消す。
- 光の筋（beam）は「狭く・カメラは円錐の外」。円錐が画面を覆うと全体がセピアに濁る。縁の薄さは `pow(dot(N,V), 2.2)` 程度。
- 浮遊塵は円錐の中だけ・少数・不透明度 0.3 以下。画面全体に散らすと星空の壁紙に見える。
- ブルームは閾値 0.96・強さ 0.32 で光源と鏡面のハイライトだけに効かせる。寄りのカットで金属が白飛びしやすい。
- 寄りで見せる小物（マイクの金網など）はテクスチャでは模様が崩れる。ジオメトリで作るか解像度を上げる。
- グレインは `master.py --grain 5`（ffmpeg の noise、時間方向に変化）で後付けする。

### P017 舞台ティザー（ゴーストライト→暗転→緞帳→スポット）から
- **スポットは必ず主役に当てる**。空の床に丸を落とすと「照明家の目」を売る見本として致命的と審査された。主役（物・人）を丸の中心に置き、結末で冒頭のモチーフ（灯った電球）を弱く再点灯させて韻を踏む。
- **意図した暗転は音もデジタルゼロにする**。絵が黒でも音楽が -30dB で鳴っていると「間」にならず、real_silence ゲートも落ちる。無音明けの最初の音は小さな具体音（綱元の擦過音など）にし、音楽は -30dB から J カットで戻す。
- **1フレーム前置きの SE と、1フレーム遅れの絵が重なると 2f（67ms）ずれる**。審査の同期は ±33ms なので、SE はイベント時刻ちょうどに置き、絵は 1f 前から立ち上げて拍のフレームで 8 割にする（指数の立ち上がりなら速度 48/秒）。
- **ライブラリ曲の拍は実音より約 35ms 遅れて解析されていた**（TNR-M04）。review.py の audio_ms が全キューで同じ符号に偏るときは、曲全体を src_in でずらして合わせる（P017 は 36ms）。
- ブルームが金属のケージに乗ると「光る針金の地球儀」に見える。灯具の金属は黒（metalness 1・roughness 0.5）にし、光るのは電球だけにする。bloom は threshold 0.92・radius 0.25・strength 0.26 程度。
- 引きの画は点光源が 1/d² で弱まり、blackdetect で黒味と判定されるほど暗くなる。引くときは光量を上げるか、引きの距離を詰める。
- 緞帳の上昇は inOutCubic だと最初の 0.3 秒がほぼ動かず黒味が延びる。inOutSine で始めから隙間を見せ、裾を遅れて揺らす（減衰サイン、0.25 秒遅れ）。
- ビームのハゼは、軸方向に引き伸ばした 4 オクターブ fbm にすると「筋」が立つ（cine.js に反映済み）。
- 文字はスタンドの支柱など縦の線と重ねない。縦型で主役が中央に立つなら、文字は主役より上にまとめる。

### 撮影書類（P023 / R009）— 「チェックリストだけで撮影が進む」の作り方
- 道具: `tools/shoot_docs.py shoot.json out.html`。スマホで上から順に見る1ページ。並びは 流れ → 担当 → 用語 → 機材 → 前日 → 設営 → 照明 → テスト → 本番 → 撮る順 → 撤収。チェックと OK のテイク番号は端末に保存（消すのは2回押し）
- 案件ごとに `checks` で全手順を書く（既定の手順への差し込みでは順番が崩れる）
- 審査で毎回見つかった抜け（次の案件で最初から入れる）:
  - **1人が同時に2か所にいる手順**を作らない（「立つ」と「見る」を別の人に）
  - **Claude は物に触れない**。手で触る作業はスタッフ、Claude は声で伝える・OBS の操作・コピー。やり取りは声の合図（「回して」「回りました」）
  - 部屋の照明を消すのはライトを点けた後
  - マイクは衣装の後に付ける
  - 録画はカメラと OBS の両方。録画中の印を目で確かめる
  - 縦の画面は横幅が狭い（2.5m・膝から上で約0.9m）。歩く芝居は両端で枠に収まるか確かめる
  - 暗い所から始める芝居はピントを手動で固定する
  - キットの電動ズームは輪に数字がない。ズームは OBS に出す枠に合わせる
  - ズームで絞りが変わるので、最初から F5.6 にそろえる
  - ヘッドホンで耳でも確かめる
  - amaran の d モデルは 5600K 固定
- 機種のメニュー名は推測で書かない（「前日に Claude と確かめる」手順にする）
- 審査は 5点 → 4点 → 5点 → 5点 → 6点。1回ごとに新しい具体的な抜けが見つかる。手順書は、実際の撮影1回で答え合わせをするのが早い

### P003 BGM ライブラリ（R008）— 合成 BGM の量産と、聴けない審査の限界
- **道具**: `tools/bgm_pack.py pack.json OUTDIR` で1ジャンルを 30秒・ループ・15秒・6秒まで一括で書き出す。帯域の自動補正（20–200Hz が 200–2000Hz より +4dB を超える分だけ 200Hz 以下を下げる）・トゥルーピーク基準の先読みリミッター（4倍オーバーサンプル、ソフトニー）・-14 LUFS ±0.2 への合わせ込み・ループ継ぎ目の検査・スペクトログラムまで自動
- **尺が割り切れるテンポを選ぶ**: 80BPM＝1小節3秒（30/15/6秒＝10/5/2小節）、120BPM＝2秒、160BPM＝1.5秒。30fps で拍がフレームに割り切れるのは 120BPM（80・160BPM は 24fps で割り切れる。beats.json の `fps_beat_exact` に出る）
- **ループの継ぎ目の作り方**:
  - 末尾の残響を頭に回す
  - その後にかけるフィルタ・揺れ・リミッター・帯域補正は、すべて3周つないで真ん中を使う（フィルタの端の状態の違いで段差が出る）
  - Lo-fi の揺れの周期はループ長の約数にする
  - 継ぎ目の指標は「直前2サンプルからの予測とのずれ ÷ 曲中で最大の同じ量」。打楽器の立ち上がりを誤検出しない
- **トゥルーピークはサンプルのピークより 2〜3dB 高くなることがある**（スーパーソーなど倍音の多い音色）。リミッターはオーバーサンプルで判定する。ハードクリップはサンプル間ピークを生むのでソフトニーにする
- **和音を `bar % 4` で回すと、最後の小節が主和音にならない**。`end_chord` / `pre_end_chord` で終止を決める。ヒーロー打撃（braam など）の音はその小節の和音と照合する（A メジャーの上の D は短9度でぶつかった）
- **「間」は1曲に2回**（30秒版）。無音で区切った区間ごとに残響を掛けて区間の終わりで切ると、暗転明けに前の残響が戻らない
- **審査の限界**: 審査エージェントは音を聴けないため、音色の質（finish_texture）を「6点が上限」とした。全軸7以上の合格条件は、聴けない審査では原理的に満たせない。音楽は数値と設計の審査に加えて、**人の耳での確認（ユーザーの試聴）を合否に入れる**必要がある（R008 でユーザーに相談）

### P002 LP（R007）— Web の作り込みと 3D の限界
- **ページの技術は合格水準**: Lighthouse モバイル 99/100/100/100、LCP 0.9〜1.0 秒、CLS 0.001 を出せた。効いたのは次の4つ。
  - Google Fonts を `text=`（ページで使う文字だけ）で取り、`media="print" onload` で非同期に読む。`display=optional` は代替フォントのまま描かれることがあるので、`text=` のサブセットと `swap` を組み合わせる
  - ヒーローは opacity でなく明るさ（filter）か、暗い画像の上に明るい画像を重ねて出す。opacity 0 から出すと LCP が遅れる
  - 和文の改行は `word-break:auto-phrase` と、句を `display:inline-block` で包む
  - 薄い文字は opacity でなく文字色で暗くする（コントラスト監査のため）
- **連番は2倍解像度で描いて Lanczos で縮小**すると細い網のちらつきが消える。ただし PC では 1080px の連番が拡大されて粗く見える。1600px 版を出し分ける。
- **カメラが光の円錐の近くにあると、ハゼが主役の手前に重なって主役が平板なシルエットになる**。密度を半分（0.28 程度）にして主役の素材を残す。
- 審査は 6.0 → 6.0 → 6.17 で頭打ち。毎回の最大の減点は「主役（マイク）が基本形状の CG に見える」（グリルが経緯線の格子でミラーボールに見える、ボディに素材のムラがない）。**手続き的に組んだ three.js のモデルは、寄りで製品写真の質に届かない**。寄りを見せ場にするなら、Blender で作り込んだモデル（P020）か実写素材が要る。

### P017 で5テイク使っても合格しなかった理由（R006）
- 審査の平均は 5.57 → 5.71 → 5.86 → 5.71 と頭打ちになった。指摘を全部直しても、次の審査員が別の弱点を見つける。**細部の修正では 6 点の壁を越えられない。越えるには、企画とキーフレームの段階で「主役の大きさ・同一性・カメラの語彙・エンドのホールド」を決め切る**。
- **ヒーローの主役は画面の 1/3 以上**（縦 1920 なら被写体の幅 260px 以上）。引きの全景で主役が 80px になると、何が照らされているか読めない（ゴーストライトがマイクスタンドに見えた）。
- **同じ主役は全ショットで同じモデル・同じ見え方**にする。寄りと引きで材質や光り方が変わると、別の物に見える。
- **文字の「6%」は字面の高さで測られる**。Noto Sans JP は font-size の約 0.77 倍が字面なので、64px の字面には font-size 84px 以上が要る（72px 指定で約 55px と判定された）。
- **エンドのホールドは最後の出来事から数える**。最終フレームの 1.0 秒前までに、すべての動き（点灯・カメラ）を終える。
- **照明のキュー（点灯・消灯・揺らぎ）には必ず音のトランジェントを付け、直前を 6〜12dB ダッキング**して立たせる。絵の明るさのピークと SE のアタックは同じフレームにする（揺らぎは 1f で立ち上げ 3f で減衰）。
- 細いワイヤやケージは SwiftShader の MSAA なしではハイライトが点線状にちらつく。2 倍解像度で描いて縮小するか、ワイヤを画面上 3px 以上にする。
- 冒頭を赤い緞帳で画面いっぱいにすると「黒地に光が色を持つ」に反すると見なされる。布は照り返しの範囲だけ色が見える暗さ（#1A0405 程度）にする。
- master.py の 2 パス linear loudnorm は、LRA が大きい（14LU 超）素材だと目標より約 +0.9LU 明るく出る。LRA を 10LU 以下に整えてから掛けると目標どおりになる。

## S03-01 キャスト解禁カード（文字版）の学び（2026-11-05・R010）
- **キーフレームの事前審査は効く**：本番レンダー（1人8秒で約45分）の前に静止画4枚で審査し、3回の修正で 4.86 → 5.86 → 6.14。審査員の見立てでは上限 6.5〜7.0 で、本番前に止められた
- **文字だけ・光だけでも 6 前後で頭打ち**：モデルの CG 感（R007）を避けても 8 点の軸が出ない。three.js の手続き的な画づくりの限界は「モデルの質」だけではなく「見せ場の強さ」にもある（R010 で判断を依頼）
- アルファ切り抜きの文字板は、影を落とさせると床に崩れた文字が出る。`castShadow=false` にして、文字幅 1.2 倍程度の柔らかい楕円を接地影として床に置く。隙間を 0 にしないと浮いて見える
- 床のクリアコートは文字の反射を段状に崩す。文字を立てる床はマット（roughness .85）
- 文字の発光（ブルーム）は安っぽく見える。文字のある画ではブルームを 0
- **逆光のシルエット**：`beam` は加算でも深度テストは効くので、光の筋を文字の完全に後ろに置けば文字が黒く抜ける。光の筋が床に刺さる線は硬い縁に見えるので、同じ場所に柔らかいスポットで床の円を作る。円は文字の下端まで届かせる（届かないと下の文字が黒地に沈む）
- 縦組みの名前は下端を y1480 以下に。カメラの lookAt を下げると床が上がり、安全域に収めやすい
- フレーム0の「灯りの気配」は 3% ではスマホで真っ黒に見える。8〜10%＋グレイン

## S05-01 舞台俳優サイトの事前審査から（2026-11-05・R011）
- Web でも、トップ4画面の事前審査で 5.83。3D モデルを使わなくても 6 前後で止まる（4作連続：P017 5.86・P002 約6・S03-01 6.14・S05-01 5.83）
- 減点の中心は「人がいない」「動きが2枚のクロスフェードだけ」「素材感がない」。**役者・音楽家のサイトは、本人の写真か映像がないと主被写体が立たない**。架空の人物では実写が用意できないので、見本として作る場合も、撮影素材（実写）の手配か、ユーザーの判断が先
- 画面に「暗転中。光っているのは…」と説明文を出すと、驚きを自分で消すと見なされる。演出は言葉で先に説明しない
- 見出しに句点を付けない（direction）。「作・演出」は中黒でつなぐ
- 舞台写真の webp を 3〜7KB まで圧縮すると、床の質感が消えてバンディングが出る。ヒーローは 150KB 級にし、ディザを入れる
- スクロール演出は、要素ごとに 80〜120ms ずつずらす。冒頭の画（暗転と印）を末尾で繰り返すと、韻を踏んだ締めになる
